# Examples

## Slack Socket Mode

`slack-socket-mode.ts` is a concrete adapter that connects Slack to `pi-channel`.

It does four things:

1. listens for `app_mention` and DM messages over Slack Socket Mode
2. forwards them to `pi-channel` with `source: "slack"`
3. polls `pi-channel` for replies per active Slack channel
4. posts replies back to Slack using `chat.postMessage`

### Required environment variables

```bash
export SLACK_BOT_TOKEN=xoxb-...
export SLACK_APP_TOKEN=xapp-...
export PI_CHANNEL_URL=http://127.0.0.1:8788
```

### Start `pi-channel`

```bash
pi-channel --allow-sources slack .
```

### Run the adapter

From `packages/channel`:

```bash
npx tsx examples/slack-socket-mode.ts
```

### Slack app setup

Use Socket Mode and grant the same core scopes/events that `mom` uses:

- bot scopes: `app_mentions:read`, `chat:write`, `im:history`, `im:read`, `im:write`, `users:read`
- for channel mentions/history as needed: `channels:history`, `channels:read`, `groups:history`, `groups:read`
- events: `app_mention`, `message.im`, and optionally `message.channels` / `message.groups`

See `packages/mom/docs/slack-bot-minimal-guide.md` for the detailed Slack setup flow.

## WeChat ilink / ClawBot

`wechat-setup.ts` performs QR login and saves credentials. `wechat-ilink.ts` runs the bridge using those credentials and the same ilink polling/send-message APIs as the `claude-code-wechat-channel` reference project.

Together they do four things:

1. logs in to WeChat via QR code and saves the bot account locally
2. long-polls `ilink/bot/getupdates` for inbound WeChat messages
3. forwards each user message to `pi-channel` with `source: "wechat"`
4. polls `pi-channel` replies per WeChat sender and sends them back with `ilink/bot/sendmessage`

### Required environment variables

At minimum:

```bash
export PI_CHANNEL_URL=http://127.0.0.1:8788
```

Then either provide credentials explicitly:

```bash
export WECHAT_ILINK_TOKEN=...
export WECHAT_ILINK_BASE_URL=https://ilinkai.weixin.qq.com
export WECHAT_ILINK_ACCOUNT_ID=...
```

Or point to an existing `account.json` generated by the reference project:

```bash
export WECHAT_ACCOUNT_FILE="$HOME/.claude/channels/wechat/account.json"
```

If `WECHAT_ACCOUNT_FILE` is omitted, the adapter looks for:

1. `~/.pi-channel/wechat/account.json`
2. `~/.claude/channels/wechat/account.json`

If neither file exists and no env credentials are provided, run:

```bash
npx tsx examples/wechat-setup.ts
```

This fetches a QR code and saves the resulting credentials to `~/.pi-channel/wechat/account.json`.

### Start `pi-channel`

```bash
pi-channel --allow-sources wechat .
```

### QR login

From `packages/channel`:

```bash
npx tsx examples/wechat-setup.ts
```

### Run the adapter

From `packages/channel`:

```bash
npx tsx examples/wechat-ilink.ts
```

### Notes

- each WeChat sender maps to its own `pi-channel` `channelId` via `from_user_id`
- the adapter reuses WeChat `context_token` values from inbound messages so replies stay attached to the active chat context
- automatic QR login uses the same ilink endpoints and credential shape as the `claude-code-wechat-channel` reference project
